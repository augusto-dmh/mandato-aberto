Profile: standard
Plan: `.specs/features/contract-v3/plan.md`

58 checks in 8 slices · 11 one-way doors (8 approved, 2 added by the orchestrator on 2026-10-02, 1 added while deriving checks) · 1 open question, which blocks go-live but not this build (rule descriptions reviewed in the PR)

All proofs run from the repository root. `P` below abbreviates `uv run --directory etl pytest`.
The feature base is `bc0a4a8` (the last commit before any code; its `etl/` equals `main`).
Fixtures are hand-built in `etl/tests/v3data.py` and served by the existing `FakeCamara`; recorded
API responses live in `etl/tests/fixtures/v3/recorded/`. The clock is pinned at
`2026-09-27T12:00:00Z` unless a check names `2027-03-01T12:00:00Z` (`2027-03-01T09:00:00` Brasília).

Three hand-built datasets carry the expected numbers, computed on paper and written next to the rows:

- **indicators** (S4): deputies 201 Ana (PT, SP), 202 Beto (PT, RJ, on leave from `2024-01-01T00:00`), 203 Caio (PL, MG); plenary roll calls P1, P2 (procedural, nominal), F1, F2 (final, nominal), A1 (amendment, nominal, government `Liberado`), S1 (final, symbolic, `2024-03-01`); committee roll call C1 (nominal)

## Test policy

The repo answers where tests live and how they run (`etl/tests`, `uv run pytest`, local HTTP fake),
not which level proves the new decision code; these rows, the same as etl-camara's, are the bar.

| Code | Required proofs | Coverage expectation |
| --- | --- | --- |
| Decides, reached across a boundary (CLI, HTTP) | one at the boundary **and** one at its own layer | exit code + stderr at the CLI; one asserted case per row of the decision table at its own layer |
| Decides, not reached across a boundary | one at its own layer | one asserted case per row of the decision table |
| Instrumentation, pass-throughs | none of its own | covered by its consumer's proof |

Evidence:

- `classify.py` (to be written): ballot over 3 outcomes (4 branch points), 11 rules with first-match, vote map over 7 rows plus unknown, orientation map over 5 rows plus empty and unknown -> decides, reached across the CLI: C17-C22, C28, C30 at its layer, C25, C29 at the CLI
- `contract_v3.py` (to be written): legislature by date (2 rows + outside), exercise periods per legislature, eligibility by ballot x organ x period x kind, two alignments, symbolic merit, proposition counts -> decides, own layer through the dataset builds: C7-C14, C31-C38
- `cli.py`: contract and house dispatch, candidacy-flag guard, version-chosen validation -> decides, at the CLI: C2-C5
- `sources/camara.py` additions: cache hit/miss per API file -> decides, across HTTP: C15, C16, C55
- `full_texts.py`: target selection over 4 cases, extraction forwarded to `pypdf` -> selection decides (C54), extraction is instrumentation
- closest analogue: `compute.py` + `tests/test_indicators.py` (etl-camara), dataset built by hand, numbers on paper next to the rows

Cost: 7 new test files, ~60 test functions. Without these rows, the rule table and the position map would be proven only by the one path the fixture build traverses.
